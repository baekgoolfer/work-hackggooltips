# Changelog

All notable changes to this project are documented in this file. The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and the project uses [Semantic Versioning](https://semver.org/spec/v2.0.0.html) (while the major version is 0, anything may change between minor versions).

## [Unreleased]

### Added

- **App installer (disk image)** (`docs/DISTRIBUTE.md`, user guide `docs/USER_GUIDE.md` and `docs/USER_GUIDE.ko.md`): `make dmg` (`scripts/build_dmg.sh`) builds `CATE-<version>.dmg` (see the Changed entry on the names), one file with the app, its pipeline, config examples, scripts and a Python runtime inside (`Contents/Resources/mcap` and `runtime`, described by `mcap/components.json`). The layout is added before signing; every nested Mach-O file and the app are signed with the identity of `scripts/build_app.sh` (no hardened runtime); the image is UDZO with an `/Applications` link and a bilingual `README-install.txt`; its sha256 is printed; `--dry-run` shows the plan; a `--hash-lock` that is not exactly the pins of `pipeline/requirements.lock.txt` is a build problem (`scripts/setup_python.sh --check-hash-lock`), a build without one warns, and `--require-hash-lock` refuses it. `scripts/fetch_python_runtime.sh` (`make fetch-runtime`) downloads the CPython 3.12 archive named in `scripts/python-runtime.lock` (URL and SHA256 are `PENDING` until you fill them, and the build refuses `PENDING`) over https only, keeps it only when the sha256 matches and writes only into the folder you give it. At the first launch the app reads, before the controller starts, whether the components are installed (a few file reads, no network); without `components-installed.json` the app **records nothing** (no detection, no "Start Recording Now", no calendar auto-start; the menu says "Auto recording is off until the installer has finished") because the recording legal notice is shown only by the helper, and the hold ends by itself when the helper has written its record. The speech model is found behind the Hugging Face cache link (`stat`, not `attributesOfItem`). If something is missing it shows one alert ("Catch Everything needs to install its components (about 4 GB download, needs internet). Start now?", **Start** / **Later**, English or Korean) and the menu item "Components: not installed - run installer"; **Start** opens `scripts/first_run_install.sh` in Terminal: a resumable, bilingual helper in seven numbered steps that runs once at a time (a `.first-run.lock` link; a second window stops and changes nothing; legal notice, checks, runtime, packages and models through `scripts/setup_python.sh`, the Anthropic key through `python -m mcap api-key set` after `api-key status --exists` asked, without reading the value, whether one is stored, `config.env` only when there is none, the meeting folder, the app's own `setup`). The app's project folder is `Contents/Resources/mcap` when it exists (a `PROJECT_DIR` in `config.env` still wins). Not run on a clean Mac; only Zoom has been verified in real calls; the alert and menu item were never seen in a real session; the app is self-signed and not notarized, so macOS warns at the first open.
- **Settings window** (menu-bar item **Settings…**, Cmd-,; `docs/SETTINGS.md`): five tabs (General, Claude, Transcription, Detection, Privacy) edit twenty `config.env` keys and the call-app list, store the Anthropic, CLOVA and OpenAI-compatible API keys in the macOS Keychain (`security -i`, the value hex-encoded on stdin, never in an argument, the environment, a file or a log; the same service and account strings as the pipeline; only "Stored in Keychain" / "Not stored" is shown), run `api-key check` (one tiny paid call), show the consent state of a cloud engine and the Google Calendar state read-only, and open Terminal with the existing commands for the consent (`asr-engines consent <engine>`) and the Google sign-in (`gcal auth`): the window never writes the consent file. The `config.env` editor is a pure function that keeps every other line, comment, unknown key, line ending and the quoting of the edited line byte for byte, refuses values the parsers would misread, parses the result with both parsers before writing, writes atomically (mode 0600) and keeps the last five `config.env.bak-settings-*` backups. Keys that an organisation policy enforces are disabled with the reason. After a save: "Saved. Restart the app to apply." with **Restart now** (never while a recording runs, then only **Restart after the recording**; and never where a relaunch would forget a pause or a call you stopped by hand and record that call again: then it waits for the call, or asks you to resume first). A stored value that is not understood is shown as what the code reads (not always the default). **Check key** is off while the organisation policy keeps the Claude lane closed. The state of the meeting folder is asked in the background after you stop typing. A read-only box states what leaves the Mac under the saved settings, in English and Korean; its decisions come from the same `EffectiveLanes` code as the menu (policy lanes, allowed engines, archive roots, consent and stored key) and it names the vocabulary list when it goes to CLOVA, Azure or the company server along with the speech. **Not verified:** the AppKit layer was drawn offscreen but never used in a real session, and the Keychain, Terminal and relaunch paths ran only against test doubles (no real Keychain).
- **New app icon and menu-bar icons.** The app icon is a clipboard with written lines and a pen (`scripts/make_icon.swift --variant D1`; `D2` a speech bubble, `D3` a notebook page with a recording dot; the former waveform icons stay available as `A`, `B`, `C`, byte for byte as before). The menu-bar symbols follow the state (`pencil.and.list.clipboard` idle, a red `pencil.and.scribble` alternating with `pencil.line` while recording, `pause.circle`, `pencil.slash`, `ellipsis.bubble`, `checkmark.circle`, `exclamationmark.triangle`), all in SF Symbols 5 with the former symbols as fallbacks (`docs/BRANDING.md`).

- **Calls of other apps** (`CALL_DETECT`, `CALL_GENERIC_SECONDS`, `EXTRA_MEETING_APPS`, `CALL_BROWSER_URLS`; `docs/DETECTION.md` section 3b): a built-in table of call apps (Slack huddles, Cisco Webex, Discord, FaceTime, Skype, GoTo, Amazon Chime, BlueJeans, Lark, KakaoTalk, WhatsApp, JANDI) is recorded like a Zoom or Teams call, `EXTRA_MEETING_APPS` adds more, and `CALL_BROWSER_URLS=on` (off by default, needs the Chrome Automation permission) reads the meeting pages of Whereby, Jitsi, Webex web, Teams web and the Zoom web client. **This is on by default and also covers personal messengers (Discord, FaceTime, KakaoTalk, WhatsApp, Skype): an existing install without `CALL_DETECT` in `config.env` starts recording those calls after the update. Set `CALL_DETECT=off` to switch it off, or switch single apps off in the new Call Apps submenu.** Only Zoom has been verified in real calls.
- **Guessing is opt-in:** `CALL_DETECT=generic` also records any other GUI app that holds the microphone and plays sound for `CALL_GENERIC_SECONDS` (45) and posts a notification that names it. It is never the default.
- Menu: **Never record `<App>`** while any call of another app is recorded, and a **Call Apps** submenu that lists every app of the table, your extra apps and the meeting-page sites (also before their first call). The decisions are kept in `call-apps.json` (mode 0600) and fail closed: a file that cannot be read pauses every call of another app and is never overwritten, a mistyped decision reads as `denied`, a decision whose write failed stays in force.
- A call of another app never blocks a Zoom, Teams or Meet meeting: that meeting takes a running call recording over after the start debounce. A guessed call is kept by the microphone (and by sound for two minutes after the microphone closed), not by sound alone.
- The four keys are on the organisation policy whitelist. On a Mac with a policy an unset `CALL_DETECT` is `off`; with `recording.enabled=false` a call of another app is skipped without a "Recording failed" notification.

### Changed

- **The bundle identifier is one build input with a neutral default.** `MCAP_BUNDLE_ID` (read by `scripts/build_app.sh`, which refuses anything that is not a reverse-DNS id before it builds) defaults to `org.meetingcapture.app` and no longer names anybody's company. It is the `CFBundleIdentifier`, the code-signing identifier and the login-agent label; the package identifier is `<id>.pkg` and the installer organisation is the id without its last label; the Swift code reads the id from `Info.plist` at run time (a bare binary falls back to the default) and derives its queue labels, own-process filter and aggregate-device prefix from it; the other scripts take it from the app they work on, then from `MCAP_BUNDLE_ID`, then the default. `make build` rebuilds when the id changes. **If you already run a build under another id, keep building it with `MCAP_BUNDLE_ID` set to that id (the Info.plist values, the signature identifier and the login-agent label are then the same as before): a different id is a different app to macOS, which then asks for the Microphone, System Audio Recording and Notification permissions again.** `scripts/build_app.sh --install` (so `make install`) refuses to replace an installed app that has another id, before it builds anything, and names the id to set. `MCAP_ALLOW_ID_CHANGE=1` switches on purpose; the old id's login agent then stays loaded and keeps starting the app, so remove it with `launchctl bootout gui/$(id -u)/<old id>` and delete `~/Library/LaunchAgents/<old id>.plist` (the script prints both, and `scripts/uninstall.sh` only removes the agent of the id that is installed). `CONTRIBUTING.md` replaces the sed recipe with this. The speech server's LaunchDaemon label is now the constant `org.meetingcapture.asr` and its template is `scripts/asr_server/org.meetingcapture.asr.plist.template`: a server installed earlier keeps running under its old label, and keeps its port, until you boot it out. List it with `sudo launchctl list | grep mcap-asr` (a normal user does not see system daemons; the last column is the old label), run `sudo launchctl bootout system/<old label>`, delete `/Library/LaunchDaemons/<old label>.plist`, then run the installer again. `scripts/asr_server/install_server.sh` now warns when it finds another `*mcap-asr*.plist` next to its own.

- **The shared product is now called Catch Everything, short name CATE, and the names of the app are build inputs next to the bundle id.** Everybody who builds this source gets the same neutral defaults. `MCAP_APP_NAME` is the human name (default `Catch Everything`): `CFBundleDisplayName`, the name in the usage strings of `Info.plist`, every alert, menu item, notification and hint of the app (the Korean ones too), the command hints and the volume of the disk image. `MCAP_APP_SHORT_NAME` is the file-safe short name (default `CATE`): the app folder `CATE.app`, its program, `CFBundleName`, `CATE-<version>.dmg` with its `.sha256`, `CATE-<version>-macos-arm64-adhoc.zip` and `CATE-<version>.pkg`. `MCAP_BUNDLE_ID` keeps its default `org.meetingcapture.app`. An empty value counts as unset. A human name must be ASCII letters, digits, spaces, hyphens and periods, start with a letter or digit, have no trailing space and be 1 to 40 characters; a short name must be ASCII letters and digits, start with a letter and be 1 to 32 characters; anything else is refused with a message before anything is built, and `scripts/bundle_id.sh` is the one place that holds the defaults and the rules. The app reads the names from its `Info.plist` at run time (a bare binary and the self tests use the defaults); the scripts read them from the installed or built app first, then from `MCAP_APP_NAME` and `MCAP_APP_SHORT_NAME`, then use the defaults; the app puts its own two names into the environment of every pipeline it starts (and the company `mcap` shim sets them), so one build has one set of names in the app, the scripts and Python. A pipeline you start by hand from a checkout, without those variables, shows the defaults. `make build` rebuilds when a name changes. `.github/workflows/release.yml` reads the repository variables `vars.MCAP_APP_NAME` and `vars.MCAP_APP_SHORT_NAME`. The README, both user guides, `docs/DISTRIBUTE.md` and the other documents now say Catch Everything and `CATE.app`; `docs/CONFIGURATION.md` has a section on the three inputs. **These did not change**, because they are paths and identifiers and not the name of the product, and renaming them would orphan data and Keychain items that already exist: the data folder `~/Library/Application Support/MeetingCapture` (and `/Library/Application Support/MeetingCapture` for the organisation policy), the log folder `~/Library/Logs/MeetingCapture`, the Keychain service strings (`MeetingCapture Anthropic API key`, `MeetingCapture ASR <engine>` and the like), the Python package `mcap`, the `MCAP_*` variables, the config keys, the login-agent label (the bundle id), the speech server's label `org.meetingcapture.asr`, the name of the local signing certificate `MeetingCapture Local Signing`, the repository and folder names, and the copyright holder line "Copyright 2026 Meeting Capture contributors" (it names the people who contributed to the repository, not the product; `docs/BRANDING.md`). **If you already run a build, keep its names:** set `MCAP_APP_NAME` and `MCAP_APP_SHORT_NAME` (and `MCAP_BUNDLE_ID`) to what the installed app already uses, and the app keeps its file name and its names. An older app file with the same bundle id next to the new `CATE.app` is refused by the install guard of `scripts/build_app.sh --install` (so `make install`), because two apps with one id would share one login agent and one set of permissions; `scripts/uninstall.sh` names such a file and does not delete it by guess, and `scripts/migrate_owner_install.sh` finds it by its bundle id (`docs/INSTALL.md` section 7). The sources and the documents name no builder and no particular build: the defaults are the same for every copy, and no one's own id or names are written into the repository. Not verified: any of this on a clean Mac. The app is still self-signed and not notarized, nothing here uploads or publishes a file, and only Zoom calls have been verified in real use.

- **The names reach every script that finds the app, the uninstall and the package guard.** The company package records its bundle id and app file name in `tools/` (`RELEASE_BUNDLE_ID`, `RELEASE_APP_SHORT_NAME`), and `sudo scripts/uninstall.sh --company` finds the app and the LaunchAgent by them (sudo does not pass your environment on); with no record (an earlier package) it takes the one app in `/Applications` that has the id, and when it can find neither the app nor the agent it stops before it deletes anything instead of removing `releases/` and `tools/` and saying done. The package's `preinstall` refuses (exit 17) a Mac that has another app in `/Applications` with the package's bundle id under another file name, before anything is put aside. `scripts/make_launchagent.sh` uses the one app in `~/Applications` that has the bundle id when `<short name>.app` is not there. `scripts/migrate_owner_install.sh` no longer picks the alphabetically first `*.app.prev` for a state record that names no app: with several it stops and asks for `MCAP_APP_SHORT_NAME`. The `Makefile` works from a checkout path that has a quote in it, and refuses `MCAP_APP_SHORT_NAME` given as a make argument (GNU Make 3.81 would not hand it to its own shell: give it in the environment). The `mcap` shim of the package and the app (for every pipeline it starts, policy or not) hand the pipeline the app's two names, and a damaged `Info.plist` can no longer stop the pipeline's command line. A test builds the real app under another name and checks `--version` and `--help` of its program.

- `ENABLED_PLATFORMS` lists Zoom, Teams and Google Meet only; calls of other apps are limited by `CALL_DETECT`, not by it (the documentation said otherwise). `scripts/install.sh` says what `CALL_DETECT` means for an existing `config.env`, and the install and login-agent texts say that the login agent records the other call apps of the table too.

- The installer texts (`dmg/README-install.txt`, the last step of `scripts/first_run_install.sh`, `docs/USER_GUIDE.ko.md`) now say which calls are recorded: Zoom, Teams and the other call apps of the table (Slack, Webex, Discord, FaceTime, KakaoTalk, WhatsApp ...), personal messengers included, Google Meet not by default, and where to switch an app off (menu **Call Apps**). The bundled Python 3.12 was checked once on the build Mac: the `cp312` hash lock installs and the packages import (`docs/DISTRIBUTE.md`).

- **The installer guide and docs are for everybody who gets a copy, not for one owner's colleagues.** `docs/EMPLOYEE_GUIDE.ko.md` is now `docs/USER_GUIDE.ko.md` (words like employee became user; no company, company Drive or "the side that distributes" assumptions; every honest limit and the platform disclosure stay: Zoom, Teams and the other call apps including personal messengers are recorded, Google Meet is off by default, the Call Apps menu), and `docs/USER_GUIDE.md` is the same guide in English; each links the other, and both now say that a self-signed, not notarized app cannot tell you who built it, so open only a file from a source you trust and compare its sha256. `docs/DISTRIBUTE.md` is written for anyone who builds and shares a copy: the recording-people and consent warning comes first, sharing goes through any file host (a GitHub release or a cloud drive link limited to the people you choose), a new section "Publishing a release on GitHub" says what to upload (the dmg and the `.sha256`, plus `LICENSE`, `NOTICE` and `THIRD_PARTY_NOTICES.md`, which the image does not hold), to paste the sha256 into the notes, to state that the app is self-signed and not notarized, and not to claim a release before it exists (nothing in the repository publishes or uploads anything), and the build section explains `MCAP_BUNDLE_ID` (the default id is shared by every copy built from this source; a distributor who ships their own signed build sets their own). `dmg/README-install.txt` (still ten lines, bilingual), the end of `scripts/first_run_install.sh`, `README.md`, `README.ko.md` (a short "Install from a disk image" pointer that claims no download), `docs/INSTALL.md`, `SECURITY.md` and the comments of the dmg scripts lost their "colleague", "owner" and company wording. `docs/POLICY.md` and `docs/ASR_PROTOCOL.md` (managed organisation deployments) are unchanged, and `docs/DEPLOY.md` and `docs/OPS_RUNBOOK.md` changed only in the bundle identifier and the speech server's daemon label. `scripts/test_scripts.sh` checks the renamed and the new guide (links in both directions, the same keywords in both languages, no real e-mail address or home folder path).

### Fixed

- Calendar auto-start skipped in-person meetings that carry a Meet link. Google Calendar attaches a Meet link to most invitations whether anybody means to join it, so the `has-conference-link` skip hid a meeting held in a booked room (a resource attendee that did not decline) or at a place name (a location without a URL or a word like online, Zoom, Teams). Such an event is now treated as in person and is recorded; an event with only a link, or a location that is a link or says online, is still left to call detection (`docs/CALENDAR_AUTOSTART.md`).

## [0.2.0] - 2026-10-17

The first version published as open source. It was developed privately before; this entry describes the whole feature set as of this release.

### Added

- **macOS menu-bar app** (Swift, built with `swiftc`, no Xcode needed) that detects Zoom and Teams calls from macOS audio and process state and records two tracks: the system audio and the microphone. Google Meet detection through Chrome tab address and title is opt-in (`ENABLED_PLATFORMS=zoom,teams,meet`). Evidence tiers keep an idle Zoom from starting false recordings.
- **Python pipeline** (`python -m mcap`): conversion to `.m4a`, echo cancellation of the microphone track, voice activity detection (energy-based, or Silero with `--with-silero`), local transcription with mlx-whisper large-v3, a hallucination filter, and a raw transcript that no LLM pass edits.
- **Claude passes** through your own `claude` tool: transcript cleanup, meeting note and a verification pass against the raw transcript. `CLAUDE_AUTH=api` is the default and the supported path (key in the macOS Keychain, budgets of 5 USD a day and 2 USD a meeting, `mcap usage`, `mcap api-key`); `CLAUDE_AUTH=subscription` is opt-in and the documentation tells you to check Anthropic's terms for unattended `claude -p` first. A cap on calls per meeting.
- **Archive and recovery:** finished meetings are moved to `ARCHIVE_DIR`; failures keep audio and transcript; `mcap reprocess` (`--last`, `--pending`, `--from <stage>`) and an automatic retry sweep; macOS notifications for start, result and problems.
- **Privacy lanes and the local-only switch:** a per-meeting **Local-Only Meeting** menu item and `LOCAL_ONLY_DEFAULT` skip every lane that can leave the Mac (external speech engines, Claude, calendar lookup, archive upload). `LOG_CONTENT`, retention keys, `mcap forget`, `mcap prune-audio` and `mcap doctor --share`. Optional external speech engines (a server of your own, Azure Speech) are off by default and need a typed consent.
- **Install and safety scripts:** `scripts/install.sh`, `scripts/uninstall.sh`, `scripts/setup_python.sh`, `scripts/make_launchagent.sh` and `scripts/make_signing_identity.sh` support `--dry-run`; the install and the confirm step show the recording legal notice and ask you to type yes (a run without a terminal needs `--accept-legal-notice`); the login agent is written only after `make confirm-live-tested`; an optional fixed self-signed identity (`scripts/make_signing_identity.sh`) keeps permissions across rebuilds; `scripts/release.sh` builds release assets without publishing anything.
- **Organisation mode (experimental):** a policy file that can only restrict, a signed installer package builder, MDM helper scripts and a central speech-to-text server, with their documents.
- **Documentation and community files:** English and Korean READMEs, install guide, an English first-run checklist (`docs/LIVE_TEST.en.md`; the full checklist `docs/LIVE_TEST.md` is Korean and opens with an English summary of every section), privacy and consent guide, third-party notices, contributing guide, security policy, code of conduct, issue and pull-request templates.
- Neutral defaults for the public release: the archive folder is `~/Meetings`, the microphone track is labelled `Me`, the example vocabulary holds only invented names and generic abbreviations, and the example `config.env` starts with `CLAUDE_AUTH=api`, small budgets (5 and 2 USD) and `CALENDAR_LOOKUP=0`. The bundle identifier, the login-agent label and the server's daemon label used the author's own reverse-DNS namespace in this release; the bundle identifier is a build input from the next one on (see Unreleased).

### Notes

- Python 3.12 or newer is required: the pinned numpy and scipy do not install on 3.11. `scripts/setup_python.sh` looks for `python3.13`, then `python3.12`, and stops early on an older interpreter.
- On a personal install (no organisation policy) `setup` reports a missing or logged-out `claude` tool as `[WARN]` instead of `[FAIL]`, so audio and transcript only use works with automatic start. With `LOCAL_ONLY_DEFAULT=1` (every new meeting starts Local-Only) a missing API key item is a `[WARN]` too.
- The microphone track is named `mic` (files `mic.wav` and `mic.m4a`, setting `MIC_AEC`).
